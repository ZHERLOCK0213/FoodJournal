# FoodJourney 项目路线图

更新：2026-09-23。此页用于说明阶段目标和候选优先级，不是发布日期承诺。实际实现与验证状态集中在 [项目状态](project-status.md)。

## 已明确的方向

- 服务对消化过程好奇的普通成年人，兼顾有慢性病史读者的理解需求；优先验证山姆会员场景，合作可行性尚未证实。
- 首用学知识，后续辅助理解选食与份量，决定由读者做出；不提供个人诊疗结论。
- 首发计划面向中国大陆，iOS 独占；无固定发布日期。
- 以持续学习、小范围实现和可复核验收推进；新技术不自动成为首发依赖。
- 当前继续本地架构，账号、云同步与 AI 功能尚未实现。

## 阶段与完成标准

| 阶段 | 主要任务 | 完成证据 | 当前状态 |
| --- | --- | --- | --- |
| 产品基线 | 明确人群、主任务、范围和数据边界 | 一致的产品规格、状态与文档入口 | 文档已整理；目标用户验证待进行 |
| 可信内容 | 核查高影响弱来源字段、区分配方和样本 | 字段来源、换算与审阅记录 | 部分建立，仍有旧估值和缺项 |
| 可靠原型 | 修正过期断言、隔离测试数据、检查异常状态 | 当前代码回归与设备体验记录 | 主流程手动验收有记录；完整回归未完成 |
| 发布候选 | 真机、无障碍、隐私、签名与商店材料 | 发布检查表与可分发构建 | 尚未完成 |
| 测试分发 | 目标读者试用、理解偏差与缺陷收集 | 问题清单、处理记录及复测 | 尚未开展 TestFlight 分发 |
| 发布与维护 | 上架、内容纠错、兼容及数据升级 | 版本记录、支持入口和维护流程 | 尚未正式发布 |

阶段可以围绕同一个小功能交叉推进，但历史测试不能替代当前回归，文档完成也不能替代功能验收。

## 候选近期工作

1. 先整理大陆标签参考、能量一致性和缺项规则；审阅现版脂肪追加提示，不能只替换参考数字。并处理测试隔离和过期断言，为下一次实现准备可复核的验收样例。
2. 以少量来源明确的山姆商品准备原型，验证标签理解、实际份量和购买比较，不承诺扫码、全库或合作接口。
3. 用 Axure 验证器官放大、分层解释及“第一份完整、后续适度加速”，观察读者能否说清食物之间有依据的差异。
4. 通过目标读者任务试用检查三页职责、单人及多人餐的误读和再次使用原因，再确定需要实现的入口与快捷方式。
5. 实现已确认的隐私政策入口，并确定设备范围、完成无障碍与真机验证；发布准备可随功能迭代逐项完成。

以上是候选顺序，具体开发任务仍需结合影响、时间和学习目标拆分，不代表已经实施。

## 决策条件

| 议题 | 进入下一步前需要的证据 |
| --- | --- |
| 山姆作为长期定位或联合品牌 | 目标读者的实际需求、数据复用条件、合作意愿及品牌授权；会员活跃不能代替这些证据 |
| 全库接入与云服务 | 小目录无法满足的具体需求、字段覆盖和更新方式、运行成本；采购需要另行决策 |
| 个人吸收量预测 | 可验证输入、可靠的对照结果、适用范围、专业支持及成本，不能仅由营养标签推导 |
| 导航改名或重组 | 用户是否理解入口，能否区分本餐成分与个人身体测量 |
| 留存能力 | 真实场景中的重复使用及原因；动画好评、初次完成不作为替代证据 |

每次迭代围绕一个可完成的问题，将需求、原型、实现、验收和复盘串起来；避免同时推进全部学习技术与产品扩张。

## 暂未进入实现范围

无边界扩充食物库、恢复旧生理容量模型、个人吸收预测、全面状态框架重构、账号云同步、AI 菜单识别与社区功能。有限商品试点可以单独验证。未来开源还需明确许可与第三方资料复用范围；开源代码不自动包含第三方商品数据授权。
