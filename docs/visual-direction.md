## 目标

让用户在没有文字解释的情况下，一眼读懂三件事：

1. 食物从张开的嘴进入；
2. 它沿一条连续路径穿过消化系统；
3. 不同器官承担不同环节，而不是一组装饰性图形。

## 构图规则

### 基础规则

- **头部**：固定为朝右的侧面，嘴保持可见且微张；食物从画面右侧进入。
- **躯干**：使用接近正面的半透明剖视，而不是强行把整个身体旋成纯侧面。这样既满足“人在进食”的方向感，也能同时读清左右分布的肝、胃与肠道。
- **连接**：口腔、咽、食管、胃、十二指肠、小肠、大肠、直肠必须形成一条不中断的主路径。
- **层级**：主消化路径最亮；参与消化但食物不直接穿过的肝、胆囊、胰腺次亮；肾等代谢相关器官更弱，避免误导为消化道的一部分。
- **镜头**：人体是舞台，器官是信息，流动粒子是主角。动画期间任何标签和泡泡都不能遮住当前粒子。

## 解剖信息规则

FoodJourney 是科普示意，不追求医学图谱般的细节，但相对位置和连接关系不能任意：

- 肝位于上腹部，以人体右侧为主；胆囊位于肝下方。
- 胃位于上腹部，以人体左侧为主，出口连接十二指肠。
- 胰腺位于胃的后下方，以细长形态出现，并以辅助分泌关系连接十二指肠。
- 小肠位于腹腔中央，以多段连续、平滑而密集的盘曲表示。
- 大肠从盲肠起，形成包围小肠的框架，再经乙状结肠进入直肠；不能画成圆角矩形。
- 肾不是食物经过的管道；仅在讲解吸收后代谢或排泄时显现。

结构依据：美国 NIDDK 对消化道的定义与示意图，包括口、食管、胃、小肠、大肠，以及肝、胰腺、胆囊等辅助器官：

- https://www.niddk.nih.gov/health-information/digestive-diseases/digestive-system-how-it-works
- https://www.niddk.nih.gov/news/media-library/18162

## 形状语言

- 所有外轮廓使用连续 Bézier 曲线和圆角连接，避免折线感。
- 小肠：较细、较亮、连续多回环；回环之间保留均匀负空间。
- 大肠：较粗、较暗、自然包围小肠；结肠袋只用柔和节律暗示，不画成串珠或硬切口。
- 胃：保留贲门、胃底、大弯和幽门方向，避免像无意义的豆形色块。
- 肝：用宽阔楔形体现体量，不能与胃左右颠倒，也不能遮死胃入口。
- 胰腺：横向细长且次要，避免被误认成第三段肠道。

## 色彩与光效

| 层级 | 建议颜色 | 用途 |
|---|---|---|
| 背景 | Midnight navy | 保持沉浸与录屏对比度 |
| 人体 | Deep indigo / cyan edge | 半透明舞台，不抢器官 |
| 食物流 | Lime → warm gold | 唯一持续运动的视觉焦点 |
| 胃 | Warm coral | 消化过程的第一个强节点 |
| 肝 | Muted burgundy | 大体量但降低亮度 |
| 胰腺 | Golden ochre | 与胃、肠区分 |
| 肠道 | Mint / teal | 表现连续与平滑 |

光效只服务于“当前发生了什么”：静态器官不应全部发光；食物经过、分解、吸收或器官被解释时才局部增强。

## 从概念图到可上线资产

概念图用于统一构图、色彩、层级与情绪，不能直接充当医学插图或动画帧。实现顺序：

1. 重绘人体侧面头部、张口和半透明躯干轮廓；
2. 建立经过审查的器官锚点与前后层级；
3. 分别重绘胃、肝、胆囊、胰腺、小肠和大肠路径；
4. 让 `DigestionPath` 与器官开口真正对齐；
5. 加入局部高亮、流动粒子与器官解释；
6. 在 iPhone 16 模拟器录屏验收，再替换正式 App Icon。

## v1 已知问题

- 概念母版的头部是侧面、躯干接近正面：这是有意的混合视角，需要在界面中用透明切面自然过渡。
- 概念母版重在视觉方向，器官比例、连接细节和流光路线仍需在矢量实现阶段校正。
- 图标中的消化线为品牌化简化，不代表完整解剖路径。
- 当前 App 内已完成轮廓、位置与路径校正；概念母版中的材质、局部光效和动效节奏尚未实现。
