## 确认 v4 测试对象

- 打开任意有食物的报告，应看到「本餐食物成分」和「胰腺参与」。
- 不再出现「内脏使用度」「实际产 ATP」「尿酸滞留」等旧模型结果。
- 点选画布左侧胰腺，下面的说明卡应有「作用讲解 ↗」。

建议先做 A–F（约 10–15 分钟）。下面的克数是**程序内置数据的验收值**，不是医学标准或饮食建议；只在 App 中预演，无需真实进食。每个独立案例从「重置饮食」开始。

## 必测

| 编号 | 操作 | 应看到什么 |
| --- | --- | --- |
| A · 连续输入 | 红烧肉 100g → 等预演结束 → 馒头 100g → 等结束 → 查看报告 | 2 份、200g；碳水 **50.0g**、蛋白 **22.0g**、脂肪 **31.1g**、纤维（不溶性口径参考）**1.3g**、食物热量 **573 kcal**。胰腺有「帮助消化」「血糖调节」两个入口。 |
| B · 不再卡上限 | 馒头 300g 预演两份，分别查看报告 | 第一份碳水 **141.0g**，第二份合计 **282.0g**；不会因为旧“能力上限”不再增加。 |
| C · 零碳水不是无作用 | 鸡胸肉 200g → 报告 → 两种胰腺作用 | 碳水 **0.0g**、蛋白 **62.0g**、脂肪 **3.8g**。消化作用仍有讲解；血糖页说明「不等于胰岛素分泌为零」，不编造分泌量。 |
| D · 重播与删除 | 重做 A → 返回画布重播最后一份两次 → 查看报告 → 食物记录中删除馒头 | 重播后仍为 2 份、碳水 50.0g；删除后剩红烧肉 100g，碳水 **3.0g**、蛋白 **15.0g**、脂肪 **30.0g**。画布不残留被删除那份的小结。 |
| E · 讲解交互 | 分别从画布和报告打开作用讲解；切换两种作用、点第 3 步、播放、暂停、播放中切换作用、关闭再打开 | 步骤与所选作用一致；暂停后高亮不再推进；切换后回到新作用第 1 步。画布入口标「本份」，报告入口标「本餐合计」，数值范围不要混淆。 |
| F · 重置 | 有两份食物时点重置，先取消，再确认重置；打开报告 Tab | 取消不改数据；确认后报告为空，不残留胰腺数值或前一份食物。回到画布能重新开始。 |

## 重点看感受，不用逐像素检查

- **看得懂吗**：胰液是送往小肠帮助消化，胰岛素是经血液参与调节，是否容易区分？有没有误以为食物穿过胰腺？
- **动画有没有抢戏**：馒头预演时，胰腺有短暂的两类提示；聚焦胃时下游食物仍可见，原来认可的器官布局不应走样。动画分段是讲解顺序，不是实际生理时间。
- **文字与点击**：滚动能看完报告、步骤卡和来源；关闭按钮始终可用。观察是否有遮挡、文字省略导致误解、点不到按钮。
- **无障碍**：可选做系统「减少动态效果」、较大字体和 VoiceOver。讲解页在减少动态效果下应仍可逐步点看；记录操作障碍，并附截图或复现步骤。
- **状态切换**：播放时短暂切到后台再回来、切换 Tab，应用应能继续使用，不崩溃、不重复加食物。无需刻意反复操作几十次。

真机尚需单独安装验证；如果只在模拟器测试，请注明。v4 工程还声明支持 iPad 和横屏，这些形态未因 iPhone 17 Pro 测试通过而自动获得验收。

## 自动化验证记录

- 旧模型诊断已通过：新会话红烧肉 100g＋馒头 100g 会改变旧胰腺数值；旧能力到上限后，使用度和胰岛素响应可停止增长。因此上限是可复现的误导机制，但尚不能确定是原问题的唯一原因。
- v4 初始阶段 **32 项通过（28 单元＋4 UI），0 失败、0 跳过**，设备为 iPhone 17 Pro / iOS 26.5 模拟器。此历史记录不代表当前版本全量测试通过。
- 已检查 [整餐报告截图](../../../Design/Anatomy/v4/previews/pork-bun-report.png)、[三步讲解截图](../../../Design/Anatomy/v4/previews/pancreas-process.png) 与 [画布胰腺入口](../../../Design/Anatomy/v4/previews/pancreas-focus.png)。
