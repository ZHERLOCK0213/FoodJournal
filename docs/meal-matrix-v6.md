# v6 餐食成分矩阵：实施与验收

2026-09-09。用户明确：报告按同类食品合并后的营养成分矩阵分析，不为每道菜重复编写完整报告；每餐上限为合并后10种食品，不是10次加入。前后端已实现，本轮52项测试均有通过记录（全量51通过，1项重播等待超时后定向复测通过）。上一轮因额度93%暂停；用户再次继续后额度恢复，已完成本轮验证。

## 数据契约

- 原始逐次记录保留，方便撤销其中一次；报告矩阵按稳定食品目录ID合并，同名但不同配方/来源记录不得合并。
- 每种食品一行统一数据：总克重、碳水、蛋白质、脂肪、热量；辅助成分仅使用可用数据，未知保持未知。
- 手机报告可将每行展示为一张紧凑成分表。整餐说明读取矩阵与合计，不依赖菜名白名单，也不从蛋白质推导嘌呤。
- 合并后最多10种。达到10种时可以追加已有种类；第11种必须明确提示并拒绝。删除某种的全部记录后释放一个名额。
- 10次100g水饺应得到1行水饺1000g。另加500g其他可用食品后为2种，不因加入11次而阻止。
- 用户的新疆炒米粉例子说明容量规则；该食品资料仍待补，不得绕过资料完整性门槛预演。用户已确认牛肉粿条为汤、原味鸡为肯德基吮指原味鸡；确认做法不等于已获取营养数据。
- 加入500g份量选项。主画布继续逐次播放，不扩大到新动画系统。

## 交互简化

胰腺帮助消化/血糖调节保留作用切换与来源。原步骤点击仅切换边框、播放仅自动轮换高亮，不提供新信息；本轮改为静态三步说明，移除无实际演示的播放按钮。不把此改动描述为已经完成器官放大教程。

## 手动验收

1. 连续加入水饺100g两次，报告应仅有一张水饺200g成分表：碳水28g、蛋白11.6g、脂肪18.4g、热量320kcal。尿酸说明不出现“水饺、水饺”。
2. 在食物记录删除其中一次，矩阵更新为水饺100g，原始记录仍可独立操作。
3. 将份量设为500g，加入一种可用食品，验证表格与整餐合计按克重缩放；新疆炒米粉仍显示数据待补且不能预演。
4. 已有10种不同食品后，第11种被禁用并显示种类上限原因；已有种类仍可追加。删除某种的全部记录后可以加入新种类。
5. 打开胰腺作用说明，三步内容可直接阅读，没有仅切换高亮的播放按钮；两种作用与来源仍可访问。

## 已落盘的后端检查点

`MealNutrientMatrix.swift`提供按catalogID合并的rows、每行values及totals；`MealEducationSummary`保留raw items/foodCount，增加matrix/distinctFoodCount，并以矩阵提供汇总。辅助字段不完整时totals对应值为nil，纤维已知小计保留独立语义。

`DigestionSession.maximumDistinctFoods = 10`，`distinctFoodCount`、`canAddEducation`及`recordEducation`门控；VM通过canEat与selectionBlockReason向UI提供原因。尿酸说明不再使用名称拼接及肉类白名单，矩阵嘌呤只读取显式metadata，不使用旧未验证估值。

新增`MealNutrientMatrixTests`三项，修改五项`UrateEducationTests`；前端已接入矩阵行表格、种类上限提示与500g选项、静态胰腺步骤，并更新相关UI断言。来源资料折叠显示，矩阵先于科普内容呈现；热量明确使用kcal单位。
