# FoodJourney 项目概览

更新：2026-09-23。

## 项目目标

FoodJourney 希望用互动示意帮助普通成年人理解食物的消化过程，并作为从需求、设计、开发、验证到发布维护的完整实践项目。

面向对消化好奇的成年人，同时关注有慢性病史读者可能产生的理解偏差。首发计划为中国大陆；当前不提供诊疗、疾病风险预测或个人营养处方。

项目以持续学习和可验收的小步迭代推进，尚无固定上架日期。功能状态见 [项目状态](project-status.md)，具体契约见 [产品规格](PRD.md)。

## 需要验证的价值

- 用户是否能通过一份食物理解器官之间的协作，而非只观看动画？
- 用户是否能分辨食物成分、一般生理机制与个人实际身体反应？
- 成分矩阵及来源是否帮助理解份量、做法和缺项？
- 用户是否有明确的再次使用场景？

目前已有维护者的功能体验记录，尚未形成独立目标用户研究或健康效果证据。上述问题是验证方向，不是已经实现的结果。

## 当前技术架构

```text
入口持有关系：
ContentView
  ├─ UserPreferences → LearningPreferencesStorage → UserDefaults
  └─ LiveSessionViewModel
       ├─ FoodLibrary → FoodLibraryStorage → 本机 JSON
       ├─ DigestionSession（本餐快照）
       └─ MealDigestionJourney（当前单份器官解释）

报告派生数据流：
DigestionSession.items → ReportView
  ├─ MealEducationSummary → 内部构造 MealNutrientMatrix
  └─ MealFocusAnalysis → 内部构造 MealNutrientMatrix
```

界面使用 SwiftUI 与 Canvas，当前会话由入口共享。应用本地计算不等于服务端；现版没有网络后端、SQL 数据库或账号系统。

旧三屏页面、旧代谢引擎与部分容量模型仍保留在源码中，但没有接入当前主报告。清理时需要检查依赖，不能仅按文件所在目录判断能否删除。

## 学习与交付物

| 方向 | 项目中的练习 | 可检查的成果 |
| --- | --- | --- |
| Axure RP 11 | 食物编辑、空状态、异常流程 | 可试用的交互原型与验收说明 |
| HTML / CSS / JavaScript | 科普素材页、介绍与支持页面 | 响应式布局、基本交互、可访问性检查 |
| SQL / MySQL | 食物、成分、来源、版本的数据练习 | 表结构、查询、约束与迁移演练 |
| Swift / SwiftUI | 输入、状态、快照、计算、界面与持久化 | 可解释的实现与针对性验证 |
| Python | 数据缺项、单位和异常值检查 | 可复现脚本与问题清单 |
| 项目管理 | 需求、取舍、版本、缺陷与复盘 | 有范围、证据和责任归属的交付记录 |

学习材料围绕真实问题安排。SQL 练习不要求立即把应用接入服务器，Python 也不是当前原生界面的替代语言。

## AI 辅助开发与未来探索

项目可使用 AI 辅助需求分析、代码、文档和资料整理。生成内容需要来源核查、人工理解与验收；AI 参与开发不等于应用已具有 AI 功能。

“自然语言菜单转食物草稿”是尚未实施的探索方向：先返回可确认的食物、份量及不确定项，再由确定性数据和计算生成展示。它不是已排期功能，也不应直接生成营养数值或医疗结论。

如后续开展该实验，应另行设计中文输入样本、人工标注、错误处理、成本预算与隐私边界；是否需要服务端由实际需求决定。

## 成本与维护

除实现时间外，还需要为内容来源核对、专业审阅、真机验证、无障碍、发布材料和用户支持留出资源。新增账号或在线服务后，还会产生数据迁移、权限、安全与持续运行成本。

本地版本也需要内容纠错、兼容更新和数据恢复策略。路线候选见 [项目路线图](project-dashboard.md)。
