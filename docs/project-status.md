## 数据与存储

| 数据或职责 | 实现 |
| --- | --- |
| 公共食物与来源 | `FoodDatabase`、`FoodDatabaseExpansion`、`FoodCompositionDatabase`，随应用打包 |
| 自建食物、最近使用 | App 沙盒 Application Support 下的 `FoodJourney/personal-foods.json` |
| 引导、关注、饮水偏好 | UserDefaults，键为 `FoodJourney.UserPreferences.v2` |
| 饭点提醒 | UserDefaults 保存时间、开关和已提示状态，键为 `FoodJourney.MealReminders.v1`；本地通知由系统调度 |
| 本餐份量 | `FoodItem` 值快照，由 `DigestionSession` 在内存中管理 |
| 汇总与分析 | `MealNutrientMatrix`、`MealFocusAnalysis` |
| 界面说明 | `FoodPresentation` 及各报告视图，与研究备注分离 |

公共数据不会被设备上的自建食物操作改写。保存成功后才更新食物库内存；文件读取失败时保留原文件并阻止覆盖。目前尚无导出、备份恢复或损坏记录修复入口。

当前没有账号、后端、云同步或云备份；本餐也不作为跨启动历史保存。可替换的存储接口只是架构准备，不代表账号隔离已实现。未来若接入账号，还需要鉴权、按账号隔离缓存、退出清理、游客迁移、冲突处理和恢复策略。

## 2026-09-25 本地未提交源码变更与验证范围

- 原画布缩放并居中选中器官，以正交折线连接两侧气泡，仅说明该器官内的过程。气泡使用“查看说明／收起说明”，说明卡在所点气泡附近随可见区域调位，长文卡内滚动，同一时间仅一张；下方可直接切换器官，覆盖 10 个器官部位。
- 收起仅关闭说明，保留聚焦；点击黑色空白才退出聚焦并关闭说明。器官、气泡、说明卡及滚动不触发退出。顶部与下方的可视“查看全貌”按钮已移除，保留 VoiceOver 返回全貌动作和退出手势。
- 内容使用当前已加入旅程的本份快照，更改下一份选择不会污染当前解释，新加入一份后随旅程刷新；无本份时仍可阅读一般作用。聚焦隐藏全消化道粒子，旅程继续且不重复计入。“减少动态效果”取消缩放插值，不改变数据。
- 大陆脂肪／碳水参考分母分别为 60 g／300 g，热量按国标的 2,000 kcal 标签等价值对照；8,400 kJ 作为来源说明，未用 4.2 充当通用换算。
- 饭点提醒源码已接入：首次实际看过有数据的报告并离开报告标签页时提示一次“是否开启饭点提醒？”，可选“允许”“定时通知”“拒绝”；默认每日 13:00、19:00，可编辑两个每日时间，“我”可更改和关闭。首次明确开启且系统权限尚未决定时才请求系统授权，拒绝不反复自动询问。系统授权选项由 iOS 控制。
- 保留“消化预演 / 代谢报告 / 我”三栏及名称，未调整导航结构。
- 已收到上一轮界面的实际运行截图反馈，本轮据此调整说明位置、按钮文字、退出方式及连线；截图反馈不表示当前全量验收通过。
- 已增加或修改内容边界、参考量、提醒及 UI 路径的测试代码。本轮核查限于静态语法、差异与文档链接，未新增构建、应用测试运行或模拟器操作记录；待项目维护者在 Xcode 中验收。
- 五款商品截图已整理为 [标签练习](learning/sams-label-pilot.md)，尚未写入 App、数据库或公共食物目录；截图未收入仓库。

手动验收建议：无餐食时点胃，确认原画布居中放大、连线均为水平或竖直折线，说明卡就近可读且长文可滚动。切换气泡和收起说明时应保留聚焦；点击器官或滚动说明不退出，点黑色空白才返回全貌，VoiceOver 返回动作也应可用。加入鸡胸肉 200 g 后查看本份蛋白，更改下一份选择后确认本份内容不变，实际再加入一份后确认刷新。切换器官、退出聚焦后检查份数与报告；检查聚焦时旅程继续、大字体与“减少动态效果”。参考量另对照 60 g 脂肪的测试输入，确认只有每日标签百分比而没有停加指令。

饭点提醒需分别验收：空报告不提示；有数据报告首次访问结束后提示一次；允许、编辑时间、拒绝及系统拒绝路径；再次访问和应用重启不反复自动询问；“我”中改时、关闭与设备实际送达。实际展示受系统通知、专注模式等设置影响，不承诺准点弹出。

## 常用操作

- 搜索：消化预演 → 全部食物 → 搜索。
- 查看或删除本餐份量：消化预演 → 查看食物记录 → 删除对应记录。
- 管理自建食物：我 → 我的食物。
- 了解保存范围或清空最近使用：我 → 数据管理。

删除本餐某份记录与删除私人食谱是不同操作；重置本餐不会清空私人食物库。

## 决策条件

| 议题 | 进入下一步前需要的证据 |
| --- | --- |
| 山姆作为长期定位或联合品牌 | 目标读者的实际需求、数据复用条件、合作意愿及品牌授权；会员活跃不能代替这些证据 |
| 全库接入与云服务 | 小目录无法满足的具体需求、字段覆盖和更新方式、运行成本；采购需要另行决策 |
| 个人吸收量预测 | 可验证输入、可靠的对照结果、适用范围、专业支持及成本，不能仅由营养标签推导 |
| 保留三栏后的理解效果 | 用户是否理解现有入口，能否区分本餐成分与个人身体测量；本轮不改名或重组 |
| 留存能力 | 真实场景中的重复使用及原因；动画好评、初次完成或通知开启不作为替代证据 |

每次迭代围绕一个可完成的问题，将需求、原型、实现、验收和复盘串起来；避免同时推进全部学习技术与产品扩张。
